# 官方进入系统流程对齐（iOS 3.6.6）

依据用户提供IPA中的`uSmartViewDesktopSDK`静态调用链及原始ARM64函数隔离执行，补齐已确认的进入系统分支。对照对象是该版本样本的协议行为；本机没有运行官方客户端，隔离执行使用合成对象和GLib/UI桩。

| 条件/阶段 | 当前行为 | 样本依据 |
| --- | --- | --- |
| 来宾连接初始化 | 能力6、终端143、登录状态16与版本23查询；能力请求时重发能力及终端信息 | `main_handle_init`、`agent_announce_caps` |
| 登录初始化与能力握手 | 待处理登录标志默认1，独立于`al`；`server-type=sy`或待处理标志发送凭据 | `0xdd3f24`、`0xe2211c → 0xe16c04` |
| 状态0 | `sy`或待处理自动登录再次发送凭据 | `0xe2543c` |
| 凭据构造 | AES预处理、URL编码、票据MD5派生XOR及BE长度；协商支持时使用RSA2048 OAEP/SHA1 | `0x11ba6b4`、`0x11bfc50`、`0xe16d50`、`0xe19a3c` |
| 登录类型 | CLI `--al`映射到`logon-noAD`，非`0`先发送85的一字节1；默认82的一字节0；CLI `--logon_type`映射到`logon-type`，空密码时处理uactoken/登录类型2的257字节82 | 129字节选项表记录38/104、`0xe79820`、`0xe1bc6c`、`0xe1bdb4` |

连接参数保留上述选项，拒绝重复选项与缺少值。每个连接最多8次凭据请求、3次状态查询，进入等待上限30秒；队列、消息及文本均保留长度限制。令牌和凭据不会进入网页结果白名单。

`fixtures/official-guest-entry.json`记录18组原始SDK隔离执行结果，使用合成token；密码发送函数在加密前拦截。对照检查比较事件顺序、消息类型与策略/token/模式报文内容，凭据编码另有原生构造与RSA回归检查。`fixtures/official-login-options.json`补充官方CLI到GObject属性的真实映射，回归从连接字符串解析一直覆盖到85/82/19发送顺序，并检查待处理标志独立于`al`。62项协议和26项网页离线检查通过。

2026-10-08早先的普通连接验证已登录桌面的连接保持，锁屏命令80未取得状态0。23:45在同一本人目标复现锁定状态无法进入；23:50补正非AD模式后，同一连接收到状态`0,0,1,1`，一次来宾凭据请求解锁，解码画面确认实际桌面。2026-10-09正常入口再次完成15秒保持、在线上报和断开清理，画面复核为Windows桌面。此次自动解锁通过85/82/19协议消息完成，没有键盘密码输入。详见[修复验证](noad-login-fix.md)。

本次对齐范围为进入系统和已登录再次连接的已确认协议分支。官方交互客户端的窗口复用、剪贴板、文件传输、键鼠活动计时和闲置锁屏退出不是本控制台的功能。121反馈只记录，不启用这些交互功能。自动关机期限没有可观察字段，续期效果仍未验证。个人账号、连接参数、原始报文和桌面画面只留本地。
