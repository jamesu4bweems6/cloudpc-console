# 官方进入系统流程对齐（iOS 3.6.6）

依据用户提供IPA中的`uSmartViewDesktopSDK`静态调用链及原始ARM64函数隔离执行，补齐已确认的进入系统分支。对照对象是该版本样本的协议行为；本机没有运行官方客户端，隔离执行使用合成对象和GLib/UI桩。

| 条件/阶段 | 当前行为 | 样本依据 |
| --- | --- | --- |
| 来宾连接初始化 | 能力6、终端143、登录状态16与版本23查询；能力请求时重发能力及终端信息 | `main_handle_init`、`agent_announce_caps` |
| 能力握手 | `server-type=sy`独立于`al`发送凭据；其他类型仅在自动登录标志仍待处理时发送 | `0xe2211c → 0xe16c04` |
| 状态0 | `sy`或待处理自动登录再次发送凭据 | `0xe2543c` |
| 凭据构造 | AES预处理、URL编码、票据MD5派生XOR及BE长度；协商支持时使用RSA2048 OAEP/SHA1 | `0x11ba6b4`、`0x11bfc50`、`0xe16d50`、`0xe19a3c` |
| 登录类型 | 默认82的一字节0；显式noAD非`0`先发送85的一字节1；空密码时处理uactoken/登录类型2的257字节82 | `0xe1bc6c`、`0xe1bdb4` |
| 能力bit17 | 发送120的4字节策略；hub-ratio精确字符串`1`设置bit1，play-lockscreen精确`1`设置bit0 | `0xe22530` |
| 状态非0 | 清除自动登录标志，执行登录后通知；只有状态1可以确认进入系统 | `0xe2543c → 0xe25034` |
| 登录后token | 有连接参数accessToken时发送124的512字节缓冲，最多511字节token；token-type精确`1`另外发送142的`<HH 1,len+1>`及NUL终止token | `0xe251ec`、`0xe24de8` |
| 用户模式 | token处理后，watch-mode参数存在即省略127，包括值`0`；否则发送非0user-mode或默认3。每次已登录通知均执行 | `0xe25034` |
| MAIN连接模式 | 无watch-mode使用1，有值时按十进制解析并取低8位 | `send_link!0xde4290` |
| 连续状态79 | 处理登录后通知，不能替代初始16确认；0也不会覆盖已有16确认 | `0xe25034`与实际16字节结构 |
| 版本24/反馈121 | 解析有界版本文本，记录锁屏断开反馈；121不是策略接受确认 | `0xe24544`及实连版本响应 |
| 桌面成功 | 同时要求有效显示帧及16状态1，完成在线业务上报、连接保持、断开上报 | 既有显示通道实现及官方连接事件链 |

连接参数保留上述选项，拒绝重复选项与缺少值。每个连接最多8次凭据请求、3次状态查询，进入等待上限30秒；队列、消息及文本均保留长度限制。令牌和凭据不会进入网页结果白名单。

`fixtures/official-guest-entry.json`记录18组原始SDK隔离执行结果，使用合成token；密码发送函数在加密前拦截。对照检查比较事件顺序、消息类型与策略/token/模式报文内容，凭据编码另有原生构造与RSA回归检查。60项协议和26项网页离线检查通过。

2026-10-08本人目标的两次普通连接在能力阶段发送凭据和120策略，收到Windows状态1，完成15秒保持、在线上报和断开清理。第二次连接画面解码确认桌面图标、任务栏及已有应用窗口。诊断锁屏命令80发出后仍观察到状态1，未取得锁定状态，所以不能把后续连接算作自动解锁验证。初次实际解锁仍来自此前复核登录框后的独立诊断密码输入。

本次对齐范围为进入系统和已登录再次连接的已确认协议分支。官方交互客户端的窗口复用、剪贴板、文件传输、键鼠活动计时和闲置锁屏退出不是本控制台的功能。121反馈只记录，不启用这些交互功能。自动关机期限没有可观察字段，续期效果仍未验证。个人账号、连接参数、原始报文和桌面画面只留本地。
